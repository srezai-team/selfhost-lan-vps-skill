# Работа с владельцем и провайдером

Агент не может подключить кабель, войти в BIOS и позвонить в поддержку. Эти шаги делает владелец — от агента нужны точные, короткие инструкции и проверка результата.

## Что спросить у владельца в начале

1. Что должно работать на сервере? (сайт, n8n, файлы, БД, мониторинг, VPN)
2. Провайдер, тип подключения, есть ли статический IP (посмотреть договор).
3. Роутер: чей, модель, есть ли доступ в админку; кто его настраивал.
4. Терминал/модем провайдера: в каком режиме (мост/роутер), можно ли звонить в поддержку.
5. Есть ли монитор и клавиатура для BIOS; готов ли владелец перезагружать сервер.
6. Кто ещё пользуется сетью (не сломать ли Wi-Fi/ТВ/камеры).
7. Где хранить доступы (менеджер паролей владельца).

## Что владелец делает руками

- Подключает патч-корд: LAN-порт роутера → Ethernet сервера.
- Заходит в BIOS (монитор + клавиатура) и меняет: автозапуск после потери питания (`Restore AC Power Loss`/`State After G3` → Power On), Wake-on-LAN (Enabled, ErP → Disabled), при нехватке RAM — размер видеопамяти (`UMA Frame Buffer Size`/`DVMT`).
- Входит в админку роутера (или даёт доступ агенту по SSH, если роутер это позволяет).
- Звонит провайдеру по скрипту ниже.
- Подтверждает результат одной строкой после каждого шага.

## Скрипт звонка провайдеру

**Подготовить:** номер договора/лицевого счёта, адрес, наклейку терминала (модель, S/N, MAC), паспорт.

**Первая фраза:** «Здравствуйте. У меня GPON/оптика, ваш терминал. За ним стоит мой собственный роутер. Нужен доступ к домашнему серверу из интернета — помогите, пожалуйста, с настройкой **на вашем терминале**. Пароль от моего роутера мне не нужен, это моё оборудование».

**Вопросы по порядку:**

| # | Вопрос | Зачем |
|---|---|---|
| 1 | «Терминал сейчас в режиме моста или роутера? Можно перевести в **мост (bridge)**, чтобы публичный IP приходил на мой роутер?» | убирает один NAT |
| 2 | «Какой **WAN-адрес** получает мой роутер за терминалом — публичный или внутренний?» | отличает двойной NAT от нормы |
| 3 | «Тип подключения — **DHCP или PPPoE**? Если PPPoE — продиктуйте логин и пароль» | без этого нельзя перестраивать роутер |
| 4 | «Статический IP при переводе в мост **сохраняется**?» | не потерять адрес |
| 5 | «Входящие **80/443** не блокируются? Это не общий **CGNAT** адрес?» | иначе проброс бесполезен |
| 6 | «Оформите заявку: номер и когда вступит в силу? Куда звонить, если пропадёт интернет?» | точка отката |

**Не спрашивать:** пароль от своей админки (`192.168.1.1` и т.п.) — это не их оборудование, ответ «не знаем» закономерен.

**Что делать с ответами:**

- «уже мост» → двойного NAT нет, проброс делать на своём роутере;
- «переведём в мост» → сразу спросить DHCP/PPPoE и креды, иначе после перевода можно остаться без интернета;
- «только DMZ» → включить DMZ на WAN-адрес роутера, дальше обычный проброс;
- «CGNAT / NAT на нашей стороне» → проброс невозможен, внешний доступ только через VPS и обратный туннель;
- «мост нельзя, проброс нельзя» → то же: VPS + туннель.

## Глоссарий для владельца

Держи объяснения на один экран:

- **GPON/ONT** — как интернет заходит: оптика в коробочку провайдера, из неё LAN.
- **WAN-адрес** — адрес устройства со стороны интернета.
- **NAT** — «секретарь с одним телефонным номером»: наружу один адрес, внутри много; входящий звонок без правила не доходит до добавочного.
- **Двойной NAT** — два секретаря подряд (терминал + роутер), правило нужно на обоих.
- **Bridge (мост)** — терминал перестаёт быть роутером и просто пропускает трафик.
- **DMZ** — весь входящий трафик на один внутренний адрес.
- **DHCP** — настройки выдаются автоматически, без логина/пароля.
- **PPPoE** — подключение по логину и паролю.
- **CGNAT** — общий внешний IP на многих абонентов, снаружи до тебя не достучаться.
- **Проброс портов** — правило «запросы на порт N из интернета отдавать устройству X».

## Протокол отчётности

После каждого шага владелец пишет одну строку: «кабель воткнут», «BIOS сделал», «провайдер сказал мост/DHCP», «DNS добавил». Агент проверяет со своей стороны и только потом идёт дальше — это защищает от работы по устаревшим фактам.
