# Ловушки: симптом → причина → что делать

| Симптом | Причина | Что делать |
|---|---|---|
| После смены сети пропал SSH/сервисы, часть трафика «теряется» | один и тот же IP на кабеле и Wi-Fi | разные адреса на интерфейсах; резерв — метрика 700; перезапустить туннели |
| `traceroute` показывает приватный хоп, выглядит как двойной NAT | у провайдера служебная сеть `10.x`/`100.64.x` | смотреть **WAN-адрес роутера**, а не трассу; приватный хоп сам по себе не диагноз |
| Пароль от админки роутера «не подходит» | регистр логина (`Admin` ≠ `admin`), блокировка после N попыток | точный регистр, подождать блокировку, искать сохранённый пароль; не брутфорсить |
| Веб-панель роутера недоступна | встроенная прошивка, урезанный UI | проверить SSH/telnet на роутере; на Linux-прошивках править nvram/конфиг и применять дельту правил |
| После правки firewall на роутере пропал интернет и доступ к серверу | перезапуск firewall сбросил NAT | не перезапускать firewall целиком; применять только добавленные правила, иметь доступ к роутеру локально |
| Смена IP сервера рвёт обратный туннель на 3–5 минут | старый сеанс на VPS держит удалённый порт (`remote port forwarding failed`) | порядок: остановить туннель → применить сеть → запустить; на VPS `ClientAliveInterval 15`/`ClientAliveCountMax 2` |
| Контейнер доступен снаружи, хотя `ufw` запрещает | Docker обходит ufw | публиковать на `127.0.0.1:<port>` + reverse-proxy или правила в цепочке `DOCKER-USER` |
| Let's Encrypt не выпускает сертификат | снаружи закрыт 80/443 или DNS ещё не обновился | проверить A-запись и доступность 80 снаружи; альтернативы — TLS-ALPN (443) или DNS-01 |
| После включения сервера мало RAM | BIOS отдал память под iGPU (`UMA Frame Buffer Size`/`DVMT`) | уменьшить до 512 МБ в BIOS, проверить `MemTotal` |
| Wake-on-LAN не работает | `ErP` включён или WoL выключен | BIOS: WoL enabled, ErP disabled; `ethtool -s <iface> wol g` + юнит на автозагрузку |
| Проверка портов «изнутри» врёт | NAT loopback на роутере выключен | проверять внешний доступ с другой машины/сети |
| Периодические ошибки TLS/расписаний | сбито время | `timedatectl set-ntp true`, проверить синхронизацию |
| Владелец проверяет порты с Windows и получает ложный результат | `Test-NetConnection`/ping могут врать (фильтры, разные сети) | проверять с сервера или с третьего хоста, смотреть логи сервиса |
